# راه‌اندازی لایسنس راست‌چین روی گپینه — چک‌لیست

این سند برای **خودِ تو** است (نه مشتری). مشتری فقط سه جمله لازم دارد که در
`docs/guide-fa.md` و `docs/faq-fa.md` آمده است.

## ۱) چه چیزی در افزونه ساخته شد

| فایل | نقش | رمزنگاری؟ |
|---|---|---|
| `gapineh-license.php` (ریشهٔ افزونه) | همان قطعه‌کد راست‌چین، بدون تغییر در ساختار | **بله** — همین فایل را به پنل راست‌چین می‌دهی |
| `includes/class-license-status.php` | خواندن وضعیت + دروازهٔ `gapineh_is_pro()` + ردیف وضعیت در تنظیمات | نه (باید خوانا بماند) |
| `gapineh.php` | بارگذاری فایل لایسنس با نگهبان `file_exists` | نه |

قطعه‌کد عیناً مطابق راهنمای راست‌چین است: نام کلاس `RTL_License_b0e384722fc261db`،
هش `5210705eb2491e92815cd01b5877475e4a69fcba`، `__DIR__`، `sha1_file` و `isActive()`.
تنها چیزی که داخل شاخهٔ `// Product is Active Now, Enable Pro Features` نوشته شده، این است:

```php
if ( ! defined( 'GAPINEH_PRO' ) ) {
    define( 'GAPINEH_PRO', true );
}
if ( function_exists( 'do_action' ) ) {
    do_action( 'gapineh_pro_active' );
}
```

چرا این‌قدر کم؟ چون منطق قابلیت‌ها در فایل خوانا (`class-license-status.php`) می‌ماند و
هر بار که قابلیت تازه‌ای اضافه می‌شود، لازم نیست فایل رمزنگاری‌شده را دوباره بسازی.
ثابت `GAPINEH_PRO` تنها چیزی است که از فایل رمزشده بیرون می‌آید.

## ۲) چرا فایل جدا و در ریشهٔ افزونه

- راهنما می‌گوید «در یکی از فایل‌هایی که در فایل اصلی include شده». ما یک فایل **تازه** ساختیم
  و در `gapineh.php` با `require_once` خواندیم؛ نتیجه همان است، ولی مزیت دارد: فقط همین یک
  فایل رمزنگاری می‌شود، نه یک فایل هستهٔ ۲۰۰۰ خطی که با هر تغییر باید از نو رمز شود.
- `__DIR__` در این فایل به **ریشهٔ افزونه** اشاره می‌کند، پس فایل لایسنس خریدار باید کنار
  `gapineh.php` باشد — طبیعی‌ترین جایی که خریدار می‌تواند فایل را آپلود کند
  (نه داخل `includes/`).

## ۳) مسیر انتشار (روی رایانهٔ خودت)

```bash
# ۱) فایل بررسی لایسنس را در پنل راست‌چین رمزنگاری کن
#    (فایل ورودی: gapineh-license.php از ریشهٔ افزونه)
# ۲) خروجی رمزشده را با همین اسکریپت جایگزین کن و بسته بساز:
bash tools/pack-release.sh /path/to/gapineh 1.0.0 \
     --encoded-license ~/Downloads/gapineh-license.php \
     --out ./gapineh.1.0.0.zip
```

اسکریپت خودش: فایل لایسنس خریدار را از بسته حذف/رد می‌کند، `verify-release.py` را اجرا
می‌کند و sha256 را چاپ می‌کند. اگر فراموش کنی رمزنگاری کنی، فقط پیام هشدار می‌گیری
(بسته کار می‌کند ولی کد بررسی لایسنس خوانا می‌ماند).

**نکتهٔ مهم:** فایل رمزنگاری‌شده بین نسخه‌ها ثابت می‌ماند؛ فقط وقتی محتوای
`gapineh-license.php` عوض شود باید دوباره رمزنگاری کنی. پس نسخهٔ رمزشده را جایی نگه دار
(مثلاً `dist/gapineh-license.encoded.php` — داخل گیت نگذار).

## ۴) رفتار افزونه در چهار حالت

| وضعیت | چه اتفاقی می‌افتد | چه چیزی در پیشخوان دیده می‌شود |
|---|---|---|
| `active` | `GAPINEH_PRO` تعریف می‌شود؛ قابلیت‌های پرو باز | «لایسنس فعال است» (سبز) |
| `inactive` | لایسنس شناسایی شد ولی `isActive()` منفی است | «لایسنس غیرفعال است» + اعلان هشدار |
| `invalid` | فایل لایسنس هست ولی هش نمی‌خواند یا کلاس بارگذاری نشد | «فایل لایسنس معتبر نیست» + اعلان هشدار |
| `missing` | فایل لایسنس خریدار نیست | «بدون لایسنس (حالت آزاد)» (کهربایی) |

**در هیچ‌کدام از این چهار حالت افزونه خطا نمی‌دهد یا سفید نمی‌شود.** یعنی می‌توانی بدون
لایسنس روی محیط تست خودت همه‌چیز را آزمایش کنی.

## ۵) اگر خواستی قابلیتی را پرو کنی

همهٔ قابلیت‌ها الان آزادند (هیچ‌چیز قفل نشده). هر جا خواستی دروازه بگذاری:

```php
if ( gapineh_is_pro() ) {
    // نسخهٔ کامل
} else {
    // نسخهٔ آزاد: پیام ارتقا یا نسخهٔ محدود
}
```

`gapineh_is_pro()` هم `GAPINEH_PRO` را می‌خواند و هم فیلتر `gapineh_is_pro` را می‌پذیرد،
پس برای تست می‌توانی با `add_filter( 'gapineh_is_pro', '__return_true' )` همه‌چیز را باز کنی
بدون دست‌زدن به فایل رمزشده.

پیشنهاد من برای نسخه‌های بعدی (اگر تصمیم گرفتی بعضی قابلیت‌ها پرو شوند): کانال بله دوطرفه،
پیامک، تیم چنداپراتوره و ساعت کاری — چون هزینهٔ نگهداری‌شان از بقیه بیشتر است. ولی برای
انتشار اول **هیچ‌چیز را قفل نکن**؛ محصولی که تازه معرفی شده باید کامل به نظر برسد.

## ۶) چک‌لیست روز انتشار

1. [ ] `bash tools/verify-release.py <درخت> <مستندات>` → همه سبز.
2. [ ] `gapineh-license.php` را در پنل راست‌چین رمزنگاری کردم.
3. [ ] `bash tools/pack-release.sh … --encoded-license …` → بسته ساخته شد و هشدار رمزنگاری نداد.
4. [ ] روی یک وردپرس تست: بدون فایل لایسنس نصب و فعال شد، هیچ خطایی نداد، ردیف «بدون لایسنس» دیده شد.
5. [ ] با فایل لایسنس خریدار: ردیف «لایسنس فعال است» دیده شد.
6. [ ] فایل لایسنس خریدار داخل ZIP نیست (`unzip -l gapineh.1.0.0.zip | grep RTL_License` → خالی).
7. [ ] ZIP را در پنل راست‌چین آپلود کردم و در «کد محصول» وضعیت تأیید شد.

## ۷) هشدارهای حقوقی که باید بدانی

- **GPL در برابر لایسنس فعال‌سازی:** هدر افزونه `GPL-2.0-or-later` است. GPL اجازه نمی‌دهد
  محدودیت اضافه (اجبار فعال‌سازی) روی توزیع بگذاری؛ در عمل بیشتر محصولات ایرانی این کار را
  می‌کنند و کسی پیگیری نمی‌کند، ولی اگر روزی شکایت/بازتوزیع پیش بیاید، همین متن هدر
  دست طرف مقابل را باز می‌کند. دو راه سازگار: (الف) هدر را به لایسنس تجاری تغییر دهیم
  (ب) نسخهٔ آزاد را واقعاً آزاد و کامل منتشر کنیم و پرو را جدا بفروشیم. تصمیمش با توست؛
  من عمداً چیزی را بدون اجازه عوض نکردم.
- **رمزنگاری و آنتی‌ویروس هاست:** برخی هاست‌های ایرانی فایل رمزنگاری‌شده را قرنطینه می‌کنند.
  اگر مشتری «فایل پیدا نشد» یا خطای parse گرفت، اولین حدس همین است. راه‌حل: نصب دستی از
  پوشهٔ `wp-content/plugins` یا درخواست استثنا از هاست.
- **رمزنگاری و به‌روزرسانی خودکار:** اگر روزی آپدیت خودکار از سرور خودت اضافه کنی، فایل
  رمزشده باید در همان بسته باشد؛ فراموش نکن.
